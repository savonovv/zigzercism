QUESTION 01

How does a mutable byte buffer work?

A []u8 is a mutable view over a sequence of bytes. The slice stores a pointer and a length: it knows where the storage begins and how many bytes are accessible, but not which bytes contain meaningful data.

var storage: [capacity]u8 = undefined;
const buffer: []u8 = &storage;

When building data incrementally, track the initialized portion with a separate cursor:

var used: usize = 0;

// Write new data starting at buffer[used].
// Advance used by the number of bytes written.

return buffer[0..used];

Core rule: buffer.len describes accessible storage. used describes initialized data.

QUESTION 02

How do I write bytes and strings into a buffer?

You can assign one byte by index:

buffer[i] = byte;

A byte slice cannot be replaced with a string using ordinary assignment. Copy the source bytes into a destination slice instead. @memcpy is appropriate when the source and destination do not overlap:

const text = "hello";
@memcpy(buffer[used .. used + text.len], text);
used += text.len;

Not valid: buffer[used .. used + text.len] = text;

Using text.len instead of a hard-coded length keeps the destination size tied to the actual source.

QUESTION 03

How do I expose only the initialized data?

Returning buffer returns its full length, including bytes you did not write. Slicing creates a view containing only the initialized prefix:

const initialized = buffer[0..used];
return initialized;

The returned slice still refers to the original storage. Slicing does not copy bytes or allocate memory, so that storage must remain valid while the returned slice is used.

QUESTION 04

Why does a buffer contain unexpected bytes?

Storage initialized with undefined has no usable initial value. Debug builds may fill untouched memory with a recognizable pattern such as 0xaa, but code must not rely on any particular value.

var storage: [capacity]u8 = undefined;

// Only storage[0..used] becomes valid after writing.

Unexpected trailing bytes usually mean that code exposed more of the buffer than it initialized. Read and return only the region known to contain valid data.

QUESTION 05

Why are buffer-formatting operations fallible?

A formatting function can run out of space, so it returns an error union such as error{NoSpaceLeft}![]u8. A function returning plain []const u8 must handle that error first.

const result = try std.fmt.bufPrint(buffer, "{d}", .{value});
return result;

When the function should allocate the formatted result, Zig 0.16 provides std.fmt.allocPrint(allocator, format, args). It calculates the required size, allocates once, writes the text, and transfers the returned slice to the caller.

Use {d} for decimal integers and floats. Default float formatting omits an unnecessary trailing .0. The {f} specifier delegates to a value's custom format method; it is not the general float specifier.

Use try when the surrounding function can return the error. Use catch when it must recover, translate the error, or when a proven size invariant makes failure impossible.

Version note: std.fmt.bufPrint is the buffer-formatting API in Zig 0.16. Standard-library names can differ between Zig versions.

QUESTION 06

How do I append multiple byte slices?

Keep a cursor and copy each selected piece at that cursor:

var used: usize = 0;

for (parts) |part| {
    @memcpy(buffer[used .. used + part.len], part);
    used += part.len;
}

return buffer[0..used];

A fixed-buffer writer is useful when many operations need to append or format data. It maintains the position and provides operations such as writeAll and print. An explicit cursor is often simpler for a small, fixed set of writes.

var writer = std.Io.Writer.fixed(buffer);
try writer.print("value={d}", .{value});
return writer.buffered();

buffered() returns only the initialized prefix. Zig slices already carry their length, so ordinary string results need neither a null terminator nor a special end-of-string byte.

Write separators between items

When exact output must not end with a separator or newline, write it only when another item follows:

for (items, 0..) |item, i| {
    try writer.writeAll(item);
    if (i + 1 < items.len) try writer.writeAll("\n");
}

A test difference showing \x0a at the expected end of string means the actual slice contains an extra newline; it does not request an end marker.

QUESTION 07

How do I reverse byte-string data?

To reverse bytes already written into the buffer, reverse only the initialized slice:

std.mem.reverse(u8, buffer[0..used]);
return buffer[0..used];

std.mem.reverse works for any mutable slice, including an ArrayList's initialized elements:

std.mem.reverse(Item, list.items);

This reverses in place in O(n) time and O(1) extra space. It needs no allocator; reverse list.items before transferring ownership with toOwnedSlice.

To copy from another slice in reverse order:

for (source, 0..) |_, i| {
    buffer[i] = source[source.len - 1 - i];
}

return buffer[0..source.len];

Text warning: This reverses bytes and is correct for ASCII. UTF-8 characters may contain multiple bytes and require Unicode-aware handling.

QUESTION 08

Which writing method should I choose?

Method Use it when
buffer[i] Writing or transforming one byte.
@memcpy Copying a complete non-overlapping byte slice.
copyForwards Preferring an explicit standard-library copy operation.
for loop Reversing, filtering, or changing bytes while copying.
std.fmt.bufPrint Producing one formatted result in caller-provided storage.
std.Io.Writer.fixed Appending many sequential or formatted pieces to caller-provided storage.
std.fmt.allocPrint Returning newly allocated formatted text whose size is not fixed by the caller.

Zig strings are byte slices, so reading existing text usually needs no writer at all: borrow a []const u8 and use loops, std.mem, or std.ascii. Use a writer when constructing output incrementally; it owns the write position, not the underlying storage.

var writer = std.Io.Writer.fixed(buffer);
try writer.writeAll("count: ");
try writer.print("{d}", .{count});
return writer.buffered();

A type can define format and use {f} when the same transformed view should be reusable inside format strings. For a one-off transformation, direct byte writes are usually simpler. Copying a string copies its bytes and does not automatically add a null terminator.

Choice rule: Start with slices. Add a fixed writer for incremental construction, and allocate only when the result must own dynamically sized storage.

QUESTION 09

Why does a function need an allocator?

A function needs an allocator when it must create runtime-sized data, whether that data is temporary or returned to the caller. The allocator is an interface for requesting and releasing memory; it is not the memory itself.

fn transform(
    allocator: std.mem.Allocator,
    input: []const u8,
) std.mem.Allocator.Error![]u8 {
    const output = try allocator.alloc(u8, input.len);

    for (input, 0..) |byte, i| {
        output[i] = std.ascii.toUpper(byte);
    }

    return output;
}

alloc(u8, input.len) requests a mutable byte slice. Allocation can fail, so try propagates errors such as OutOfMemory.

Temporary collections can also use an allocator and free their storage before the function returns. Dynamic containers request more memory as they grow, so the caller does not need to know their final size. If an implementation needs no dynamic storage, an allocator parameter may remain unused.

Ownership

Unless an API documents otherwise, the caller owns a returned allocation and must release it with a compatible allocator:

const result = try transform(allocator, input);
defer allocator.free(result);

// Use result here.

Lifetime mistake: Do not return a slice pointing to a local array. Local storage stops being valid when the function returns. Allocated storage remains valid until its owner frees it.

Ownership rule: The code that receives ownership is responsible for arranging exactly one matching free, usually immediately with defer.

QUESTION 10

How do I associate numeric data with enum values?

An enum represents a closed set of identities. Its backing values must be integers, so an enum cannot directly store a floating-point coefficient. Keep the identity in the enum and map each tag to its data with a method and a switch expression:

const Tier = enum {
    basic,
    premium,

    fn coefficient(self: Tier) f64 {
        return switch (self) {
            .basic => 1.0,
            .premium => 1.5,
        };
    }
};

A switch returns one value for one input. Its cases must be known at compile time, so runtime values from a slice belong in a loop rather than dynamically generated switch cases. Multiple fixed cases can share one result, such as 'a', 'e' => 1.

Inferred literals and enumeration

When context already expects an enum type, a leading-dot literal omits the repeated type name. A function parameter of type Status lets setStatus(.busy) mean setStatus(Status.busy). Without an expected type, write the qualified form.

const Status = enum(u8) {
    idle = 0,
    busy = 1,
};

const current: Status = .busy;
const code: u8 = @intFromEnum(current);

An enum is not indexed like an array. In Zig 0.16, std.enums.values(Status) returns a []const Status containing every named value in declaration order. Use @tagName(value) when the textual tag name is needed. @TypeOf reports an expression's type; it does not enumerate tags.

Exhaustiveness: Zig requires every possible enum tag to be handled. Adding a new tag therefore points directly to mappings that need updating.

QUESTION 11

Why does integer-to-float calculation order matter?

Zig does not implicitly mix integer and floating-point types. Convert an integer explicitly with @floatFromInt, giving the result a concrete float type:

const count: usize = 95;
const count_float: f64 = @floatFromInt(count);
const average = count_float / 3.0;

Convert before division when the fractional part matters. In @floatFromInt(count / 3), integer division happens first, so the fraction is already lost before conversion.

Precision versus formatting

An f64 does not store a fixed number of decimal digits. Output formatting controls only how the value is displayed:

std.debug.print("{d:.2}\n", .{average});

This prints two digits after the decimal point but does not change average. When testing a calculated float, compare it with a tolerance using std.testing.expectApproxEqAbs instead of formatting it or expecting exact equality.

Common mistake: Converting after integer arithmetic changes the result's type, but it cannot restore a fractional part that integer division already discarded.

QUESTION 12

How can loop order prevent duplicate counting?

When several rules can select the same item, iterating by rule can generate that item more than once. Iterating by item instead gives each item one opportunity to contribute:

outer: for (items) |item| {
    for (rules) |rule| {
        if (matches(item, rule)) {
            total += item;
            continue :outer;
        }
    }
}

The labeled continue stops checking rules after the first match and advances the outer loop. This uses constant extra memory because no set of previously seen items is needed.

The tradeoff is time: checking every item against several rules takes work proportional to the number of items times the number of rules. Generating items rule by rule can do less work, but overlapping results then require deduplication, such as a set or a problem-specific mathematical method.

Range boundary: Zig ranges are ascending and end-exclusive. A runtime range such as 1..0 is not an empty descending range and can overflow while iterating. Represent the empty case without placing a larger start before a smaller unsigned end.

QUESTION 13

How do I test that a function returns an expected error?

Pass the function's unresolved error union directly to std.testing.expectError:

try std.testing.expectError(
    error.Invalid,
    parseValue(input),
);

Do not put try around parseValue(input). That would propagate the expected error before expectError could inspect it. The outer try instead handles the assertion's own result: the test fails if the call succeeds or returns a different error.

Mental model: Give expectError the unopened error union. Let the helper verify which branch and which error it contains.

QUESTION 14

When can I omit a struct's type name?

When the expected type is already known from context, begin a struct literal with .{ instead of repeating its type:

const Point = struct {
    x: f64,
    y: f64,
};

fn origin() Point {
    return .{ .x = 0, .y = 0 };
}

The function's return type tells Zig that the literal is a Point. The same inference works in other contexts with a known expected type.

Named fields remain required: Ordinary structs do not support positional initialization. Write .x = value, not just value.

QUESTION 15

How do I tokenize input and allocate an exact-size result?

std.mem.tokenizeAny treats any byte in its delimiter slice as a separator and skips empty tokens created by repeated delimiters:

var iterator = std.mem.tokenizeAny(u8, input, " \t-_");

while (iterator.next()) |token| {
    // token is a non-empty []const u8.
}

next() returns ?[]const u8, not bool. Optional capture unwraps each token and ends the loop when the iterator returns null.

State and allocation

Token iterators are stateful and one-way. After one loop reaches the end, a second loop over the same iterator receives nothing. Recreate the tokenizer when using two passes:

var counter = std.mem.tokenizeAny(u8, input, delimiters);
var count: usize = 0;
while (counter.next()) |_| count += 1;

const output = try allocator.alloc(u8, count);

var tokens = std.mem.tokenizeAny(u8, input, delimiters);
// Fill output from tokens.

A two-pass design avoids guessing the output size: count first, allocate exactly once, then fill. Use usize for allocation lengths and slice indexes because it is the native size type used by Zig's memory APIs.

Uninitialized output: Allocated bytes initially contain no meaningful values. If a consumed iterator makes the write pass skip every assignment, returning the full allocation exposes those uninitialized bytes.

QUESTION 16

How do I print debugging information while running tests?

std.debug.print writes formatted output to standard error without requiring an allocator or error handling. Its output appears alongside the normal zig test results:

std.debug.print(
    "input={s}, index={d}, byte={c}\n",
    .{ input, index, byte },
);

Use {s} for byte strings, {d} for decimal numbers, {c} for characters, and {any} for a general representation. Include labels and a newline so repeated calls remain readable.

When inspecting a partially initialized buffer, print only its valid region:

std.debug.print("result={s}\n", .{buffer[0..used]});

Temporary versus permanent: Use debug prints to investigate control flow and intermediate values, then remove them. Use std.testing assertions for permanent checks because they produce structured failures.

QUESTION 17

How can I compare distances without calculating a square root?

When only the ordering of Euclidean distances matters, compare squared values. Squaring preserves the order of non-negative distances, so the square root is unnecessary:

const distance_squared = x * x + y * y;
const radius_squared = radius * radius;

if (distance_squared <= radius_squared) {
    // The point is inside or on the circle.
}

Direct multiplication is also clearer than a generic power function when the exponent is exactly two. This avoids both sqrt and pow while preserving boundary comparisons.

Recognize diagonals from coordinate differences

Two grid positions share a diagonal when the absolute row difference equals the absolute column difference:

const same_diagonal = @abs(a.row - b.row) == @abs(a.col - b.col);

Validate the coordinate range before subtracting signed integers so the differences cannot overflow. If distinct positions are required, reject equal coordinates first: zero row difference and zero column difference also satisfy the equality above.

Flatten classifications with early returns

When checking ordered thresholds, test them from the most restrictive outside case toward the inside and return immediately:

if (value > largest_limit) return outside;
if (value > middle_limit) return outer_band;
if (value > smallest_limit) return middle_band;
return inner_band;

Why it helps: Early returns remove unnecessary else nesting, and squared comparisons avoid computing a value that the classification does not need.

QUESTION 18

How do I process decimal digits and integer powers?

When the input is already an integer, no tokenizer is needed. Remainder by ten reads the last decimal digit, and integer division by ten removes it:

var value = original;
while (value > 0) : (value /= 10) {
    const digit = value % 10;
    // Use digit here.
}

Use a mutable copy so the original remains available after the loop. Handle zero deliberately because the loop body does not run when the initial value is zero.

Powers and shifts

Zig has no numeric exponentiation operator. In Zig 0.16, std.math.pow computes a numeric power. The ** operator repeats arrays and therefore expects a compile-time-known repetition count.

Bit shifting is different: for an integer result that fits, x << n multiplies by 2^n. Thus x << 1 doubles and x << 2 multiplies by four; neither operation squares x. Floating-point values cannot be shifted.

To process an integer one binary digit at a time, mask the lowest bit with value & 1, then remove it with value >>= 1. This is the base-two analogue of reading a decimal digit with remainder by ten and removing it with division by ten.

For a runtime shift, give the left operand a fixed-width integer type and validate the shift amount before subtracting or shifting. A geometric sequence that fills every bit of an unsigned type sums to that type's maximum value: std.math.maxInt(u64) is 2^64 - 1 without attempting to represent the out-of-range value 2^64.

Type rule: Keep accumulators wide enough for the input domain. A usize accumulator is not sufficient for calculations over arbitrary u128 values.

QUESTION 19

When should I replace a loop with a closed-form formula?

A loop is often the clearest first implementation. When a well-known formula exists, it can reduce work from linear time to constant time:

const sum = n * (n + 1) / 2;
const square_of_sum = sum * sum;
const sum_of_squares = n * (n + 1) * (2 * n + 1) / 6;

Name intermediate values so the code preserves the mathematical distinction between a sum and the square of that sum. Returning sum where sum * sum is required can also make later unsigned subtraction underflow.

Overflow tradeoff: Constant-time formulas may create large intermediate products. Divide factors before multiplication where algebra permits, or use a wider checked type when the input range requires it.

QUESTION 20

How do I initialize, iterate, and return an AutoHashMap?

An AutoHashMap manages its own dynamic storage. Initialize one map with an allocator; allocator.alloc(Map, count) would instead create a slice of map objects:

var result = std.AutoHashMap(u8, u32).init(allocator);
errdefer result.deinit();

Insertion can allocate, so put is fallible. The errdefer cleans up partial construction if an insertion fails, but does not run when ownership is successfully returned to the caller.

Iteration

An iterator must be mutable because next() advances its cursor. Entries expose pointers to their stored key and value:

var iterator = map.iterator();
while (iterator.next()) |entry| {
    const key = entry.key_ptr.*;
    const value = entry.value_ptr.*;
}

Iteration order is unspecified. Do not insert or remove entries through the map while its iterator is active.

Ownership and capacity

Use ordinary defer map.deinit() in the scope that owns and consumes the map, so cleanup also runs when a later operation fails. Use errdefer while constructing a value that will be transferred on success.

A map grows automatically, so counting input first is not required. If the final entry count is already known cheaply and the map is large, ensureTotalCapacity can reserve space before insertion. A separate counting pass is a tradeoff: it may reduce reallocations but adds another full traversal.

Optimization rule: For small maps, prefer one clear insertion pass. Reserve capacity when scale or measurement justifies the extra logic.

QUESTION 21

Do I need to store a slice's size separately?

No. A slice stores a pointer and a length, available as slice.len. A separate size field duplicates state and can become inconsistent.

[3]T         // array value; length is part of the type
*const [3]T  // pointer to an exact three-element array
[]const T    // read-only slice; pointer and runtime length

A slice is not lengthless: check slice.len > index before indexing when the caller may provide short input. A fixed-bound expression such as slice[0..3] can produce a pointer to an exact three-element array; that pointer is still different from the array value itself.

Check for an empty slice before indexing its last element or using an aggregate that requires data:

if (values.len == 0) return null;

const latest = values[values.len - 1];
const greatest = std.mem.max(i32, values);

In Zig 0.16, std.mem.max scans a non-empty slice in linear time and performs no allocation. For pairwise processing, a multi-sequence loop traverses equal-length slices in lockstep:

for (left, right) |a, b| {
    if (a != b) differences += 1;
}

Validate equal lengths before the loop. This gives O(n) time and O(1) extra space, which is optimal when every pair must be examined.

Lifetime rule: Do not return a slice into a local array created inside the function. Returned slices must refer to storage that remains alive, such as caller-owned input, struct-owned storage, or an allocation transferred to the caller.

QUESTION 22

How do I keep a sorted top-k result in a fixed array?

A fixed array has a compile-time capacity, not a runtime empty state. Pair it with a logical length:

var values: [capacity]i32 = undefined;
var used: usize = 0;

Only values[0..used] is initialized. Search that prefix for the insertion position; use values.len only as the physical capacity. After deciding that an item belongs, compute the new length, shift the affected tail right, insert once, and update used.

Backward shift

To insert 100 at index zero in [90, 70, 30], copy from the back so no unread value is overwritten:

90  70  30
90  70  70  // copy index 1 to index 2
90  90  70  // copy index 0 to index 1
100 90  70  // write the new value at index 0
var j = new_len - 1;
while (j > insert_at) : (j -= 1) {
    values[j] = values[j - 1];
}
values[insert_at] = item;

Changing j only moves the cursor; the assignment in the loop body moves the data. A forward shift would overwrite the source for the next copy.

Compile-time capacity

To reuse the same bounded container with different fixed capacities, return a type from a function taking a comptime parameter:

fn Bounded(comptime capacity: usize) type {
    return struct {
        values: [capacity]i32 = undefined,
        used: usize = 0,
    };
}

var small = Bounded(3){};
var larger = Bounded(5){};

Each capacity creates a distinct type. Inside it, values.len is the capacity, so the algorithm does not repeat a hard-coded number. A runtime capacity instead requires allocated slice storage and an ownership policy.

Invariant: values[0..used] is initialized and sorted. values[used..values.len] is never read. The logical length never exceeds capacity.

For capacity k and n inputs, bounded insertion takes O(n * k) time and O(k) storage. When k is a fixed small constant, such as three, that is O(n) time and O(1) extra storage.

QUESTION 23

How do I combine encoded digits and format metric units?

Combine decimal digits with place-value arithmetic rather than text concatenation:

const pair = first_digit * 10 + second_digit;
const raw = pair * std.math.pow(usize, 10, exponent);

For enum digits, obtain each backing integer with @intFromEnum. A general digit fold follows the same rule: multiply the accumulated value by ten, then add the next digit.

Choose a metric prefix

Keep the raw value unchanged and advance through a small declaration-order unit table while scaling by groups of one thousand:

const units = [_][]const u8{
    "", "kilo", "mega", "giga",
};

var scaled: f64 = @floatFromInt(raw);
var unit_index: usize = 0;
while (scaled >= 1000 and unit_index + 1 < units.len) {
    scaled /= 1000;
    unit_index += 1;
}

Then std.fmt.allocPrint can produce the allocated label using {d} for the scaled number and {s} for the selected prefix. For exact financial or measurement semantics, retain an integer divisor and use quotient/remainder instead of floating point.

Separation rule: The raw value represents the quantity; the divisor or scaled copy represents display units. Do not destroy the raw value while deciding how to format it.

QUESTION 24

Which standard-library sort should I use?

In Zig 0.16, std.mem.sort and std.mem.sortUnstable sort mutable slices in place. Choose based on whether equal elements must retain their original relative order:

std.mem.sort(i32, values, {}, std.sort.asc(i32));
std.mem.sortUnstable(i32, values, {}, std.sort.desc(i32));

std.mem.sort is stable with O(n log n) average and worst-case time. std.mem.sortUnstable uses pattern-defeating quicksort, does not preserve equal-element order, and is generally faster. Both mutate the supplied slice.

Ownership changes the choice

A []const T input cannot be sorted in place. Sorting it would require a mutable owned copy, and that copy needs storage and a lifetime policy. Sorting also destroys the original order, which matters when APIs need both sorted results and insertion-order information.

Top-k rule: Sorting all n values costs O(n log n). Keeping only a fixed number k of best values can remain O(n) when k is a small compile-time constant.

QUESTION 25

How do I turn an integer bitmask into an EnumSet?

When only the low bits are part of a format, narrow a larger unsigned integer with intentional truncation:

const relevant: u8 = @truncate(value);

@intCast requires the complete value to fit and traps when it does not. @truncate deliberately discards high bits, which matches bitmask formats that define unknown high flags as irrelevant.

EnumSet.init accepts a struct of named booleans, not a runtime integer mask. Build a runtime set from empty storage and insert matching enum values:

var set: std.EnumSet(Flag) = .empty;

for (std.enums.values(Flag)) |flag| {
    if (hasFlag(relevant, flag)) set.insert(flag);
}

Membership is bitwise, not numeric

A larger encoded score does not necessarily contain a particular flag. For a dense zero-based enum with at most eight tags, map a flag to its one-bit mask, then use bitwise AND:

const bit: std.math.Log2Int(u8) = @intCast(@intFromEnum(flag));
const mask: u8 = @as(u8, 1) << bit;
return value & mask != 0;

A switch can match fixed values and inclusive ranges such as 0...10, but it has no relational case syntax like > 10. More importantly, magnitude comparisons are the wrong model for independent bit flags.

Set, test, clear, and toggle flags

Give each independent fact one named bit. Names preserve the compact representation without forcing readers to decode magic binary literals:

const has_letter: u8 = 1 << 0;
const has_lowercase: u8 = 1 << 1;
const is_question: u8 = 1 << 2;

state |= has_letter;                 // set
const set = state & has_letter != 0; // test
state &= ~has_letter;                // clear
state ^= has_letter;                 // toggle

To extract one bit as the integer 0 or 1, shift it to the lowest position and mask it: (state >> bit_index) & 1.

Combined states are ordinary bitwise OR results. Derive semantic conditions by testing the relevant bits rather than listing every possible numeric mask. For example, an all-uppercase state requires at least one letter and no lowercase letters; without the first condition, punctuation and numbers would be misclassified.

Keep control bits separate from an output enum when they alter processing but are not valid output values. This prevents the public result type from representing states the function should never return.

Bitmask rule: Normalize the relevant bits, test each flag independently, and never infer membership merely because the encoded number is larger than a flag's value.

QUESTION 26

How do I compare unordered ASCII text without collisions?

Checksums, bit sets, and fixed-width products are only fingerprints: different inputs can collide, duplicate counts can disappear, and arithmetic can overflow. When the alphabet is small and known, count each symbol instead:

fn frequencies(text: []const u8) [26]usize {
    var counts = [_]usize{0} ** 26;

    for (text) |character| {
        const lower = std.ascii.toLower(character);
        const index: usize = lower - 'a';
        counts[index] += 1;
    }

    return counts;
}

Fixed arrays can be returned safely by value and compared as slices:

const same = std.mem.eql(
    usize,
    left_counts[0..],
    right_counts[0..],
);

Lifetime mistake: Returning counts[0..] from a function returns a slice into a local stack array. The array expires at function return, leaving a dangling slice. Return [26]usize by value instead.

For case-insensitive identity checks, use std.ascii.eqlIgnoreCase rather than allocating lowercase copies. Frequency construction takes O(n) time and the 26 counters use O(1) space.

QUESTION 27

How do I clean up owned resources when construction fails?

A function that builds and returns an owned container transfers cleanup responsibility to the caller only on success. If a fallible operation fails first, the function still owns the partially built value:

var result = Container.init(allocator);
errdefer result.deinit();

try result.insert(value);
return result;

errdefer runs only when the current scope exits with an error. On success it does nothing, allowing ownership to move to the caller. A regular defer would also run on success and destroy the value immediately before it is returned.

Clean up nested allocations

An outer slice of owned slices has two allocation levels. Track how many entries contain initialized, owned values so an error path never reads or frees undefined entries:

const items = try allocator.alloc([]u8, count);
errdefer allocator.free(items);

var initialized: usize = 0;
errdefer {
    for (items[0..initialized]) |item| {
        allocator.free(item);
    }
}

items[initialized] = try createOwnedItem(allocator);
initialized += 1;

errdefer actions run in reverse declaration order, so initialized child allocations are released before their outer slice. Increment the logical count only after a child allocation succeeds. On success, the caller must mirror the same ownership graph: free each child, then free the outer slice.

Ownership rule: Before every fallible step, know who cleans up resources already acquired. Use errdefer while constructing an owned return value, and let the successful receiver arrange its matching deinit.

QUESTION 28

Which strategy should I use for an integer square root?

A linear search is a valid first implementation: test successive integers until the square reaches the radicand. It takes O(sqrt(n)) time and O(1) space, which is practical for small inputs.

For larger domains, binary search reduces the work to O(log n). Compare a candidate with radicand / candidate rather than multiplying candidate * candidate when the multiplication could overflow.

A bit-by-bit integer-root algorithm processes powers of four using shifts, comparisons, and subtraction. In Zig 0.16, std.math.sqrt already uses this approach for unsigned integers and returns the floor of the root, but an exercise may intentionally require implementing the operation without the math library.

Contract rule: If inputs are guaranteed to have whole-number roots, a search may stop on equality. For arbitrary inputs, decide explicitly whether the result should be the floor, ceiling, nearest integer, or an error.

QUESTION 29

How do half-open bounds make binary search safer?

Represent the active search region as [left, right): left is included and right is excluded. Initialize left = 0 and right = items.len, then continue while left < right. An empty slice naturally starts with equal bounds.

const middle = left + (right - left) / 2;

if (items[middle] < target) {
    left = middle + 1;
} else if (items[middle] > target) {
    right = middle;
} else {
    return middle;
}

The midpoint formula avoids overflowing left + right. Assigning right = middle avoids unsigned middle - 1 underflow. Return null after the bounds meet.

Generic element types

fn search(
    comptime T: type,
    target: T,
    items: []const T,
) ?usize

The element type is selected at compile time while indexes remain usize. Binary search requires sorted random-access input, takes O(log n) time, and uses O(1) extra space.

Progress rule: Every comparison must either return or shrink the half-open region. If equality changes neither bound, the loop never terminates.

QUESTION 30

How does pseudo-random state work?

A pseudo-random generator is a deterministic state machine. Its seed selects a sequence, and every generated value advances the state:

var prng = std.Random.DefaultPrng.init(123);
const random = prng.random();

const die = random.intRangeAtMost(i8, 1, 6);

intRangeAtMost includes both endpoints; intRangeLessThan excludes the upper endpoint. Reinitializing a generator with the same seed before every draw repeats its first value, so generator state must outlive the sequence of draws.

A fixed seed is useful for reproducible tests but repeats the same sequence on every process start. A CSPRNG with a hard-coded seed has the same limitation; changing the algorithm does not create entropy.

Lifetime mistake: A std.Random interface points to generator state. Do not obtain it from a temporary generator that immediately expires. Store the generator for at least as long as the interface is used.

When an API requires a fixed byte-array seed, remember that a string literal has pointer type such as *const [32:0]u8. Dereference it with .* when an array value is intentionally required.

QUESTION 31

Where should randomness come from?

There is no truly seedless PRNG. APIs that appear seedless obtain and manage entropy through another dependency, typically operating-system I/O. In Zig 0.16, std.Random.IoSource adapts std.Io to the common random interface:

fn choose(io: std.Io) u8 {
    var source: std.Random.IoSource = .{ .io = io };
    const random = source.interface();
    return random.intRangeAtMost(u8, 1, 6);
}

In an application, create or receive std.Io near the entry point and pass std.Io or std.Random down through the call chain. This dependency injection makes tests deterministic and avoids hidden global state.

API tradeoff: A fixed callback signature with no random parameter may force persistent module state. That can be acceptable for a small single-threaded exercise, but shared mutable PRNG state requires synchronization in concurrent code.

QUESTION 32

Can I select struct fields at runtime?

Struct and tuple field names, types, and offsets are compile-time information. Use inline for when reflecting over fields so Zig unrolls one access per field:

inline for (std.meta.fields(T)) |field| {
    const value = @field(instance, field.name);
    // value is used at runtime; field selection is compile-time.
}

In Zig 0.16, @typeInfo(T).@"struct".fields exposes field metadata; there is no field_names member. For homogeneous values that require runtime indexing, use an array and a regular for loop instead of reflection.

Data-shape rule: Use structs for named fields with distinct meaning. Use arrays when elements share one type and should be processed uniformly at runtime.

QUESTION 33

How do I divide signed integers with explicit rounding?

Zig requires signed integer division to state its rounding rule explicitly:

const toward_zero = @divTrunc(numerator, denominator);
const toward_negative_infinity = @divFloor(numerator, denominator);
const exact = @divExact(numerator, denominator);

The distinction matters for negative odd values: truncating -7 / 2 gives -3, while flooring gives -4. Use the operation that matches the domain rule rather than applying floating-point @floor to integer arithmetic.

Intent rule: Explicit division builtins make negative-number behavior visible and prevent an implicit rounding assumption from becoming a boundary bug.

QUESTION 34

How do I parse immutable text without creating another string?

Zig text is usually a byte slice. A u8 is one byte; []u8 is a pointer-and-length view whose bytes may be changed; []const u8 is the same kind of view but its bytes may only be read. Iterating a slice copies one byte into the loop capture:

for (input) |byte| {
    // byte has type u8.
}

The const in []const u8 applies to the viewed bytes. This differs from a constant binding to mutable bytes:

var storage = [_]u8{ '1', '2', '3' };
const writable: []u8 = &storage;
writable[0] = '9'; // allowed

Trimming is not filtering

Trimming an edge can return a smaller slice because the retained bytes remain contiguous. Removing bytes from the middle cannot be represented by one slice: producing compacted text requires mutable or separate storage. Parsing often needs neither. Classify each byte and calculate the result during the same pass:

for (input) |byte| {
    if (byte == allowed_separator) continue;
    if (!std.ascii.isDigit(byte)) return false;

    const digit = byte - '0';
    // Consume digit directly.
}

Subtract '0' only after validating the byte as an ASCII digit. Use {c} to print a byte as a character, {d} to print its numeric value, and {s} for a byte slice.

Parsing rule: Skip only explicitly allowed separators. Reject unknown bytes instead of silently filtering them, and build a new string only when compacted text is itself the required output.

QUESTION 35

How do I convert between enum names, values, and encoded bytes?

These conversions represent different directions. A runtime string can be matched against enum tag names with std.meta.stringToEnum. The result is optional because the name may not exist:

const selected =
    std.meta.stringToEnum(Choice, name) orelse return error.UnknownChoice;
const offset = @intFromEnum(selected);

@intFromEnum then extracts an actual enum value's backing integer. It cannot operate directly on the original string.

When an enum deliberately uses encoded byte values, @enumFromInt performs the reverse conversion:

const Symbol = enum(u8) {
    alpha = 'A',
    beta = 'B',
};

const symbol: Symbol = @enumFromInt(byte);

The expected result type tells Zig which enum to construct. Validate untrusted bytes first because a byte that is not a declared backing value is an invalid enum value.

Index encoded rows without copying

For two equal-width rows separated by one newline, indexOfScalar returns the newline's index, which is also the first row's width. The second row begins one byte later:

const row_width =
    std.mem.indexOfScalar(u8, input, '\n') orelse return error.MissingRow;
const row_stride = row_width + 1;
const index = row * row_stride + column;

Validate the final required column against row_width and the final computed index against input.len. Comparing a column only with the total input length is incorrect because that length includes both rows and the separator.

Representation rule: Convert tag names with stringToEnum, convert enum values to backing integers with @intFromEnum, and convert validated backing integers with @enumFromInt.

QUESTION 36

Should I calculate formatted output size myself?

When a function already receives an allocator and returns owned text, let the formatter manage decimal digit counts, separators, and fixed text:

return std.fmt.allocPrint(
    allocator,
    "{s}: {d}{s}",
    .{ label, number, suffix },
);

{s} formats byte strings and {d} formats a number in decimal. The result is an allocated []u8 that the caller must free with the matching allocator.

When an exact caller-managed allocation is genuinely required, std.fmt.count computes the formatted length and std.fmt.bufPrint writes into that storage. This performs a counting pass and a writing pass, so allocPrint is usually clearer for an owned return value.

Size mistake: @sizeOf(number) is the number's binary storage size, not the number of decimal characters it produces. Manual size formulas must also include every fixed byte, separator, and suffix.

Apply exception rules before general rules

Suffix systems often inspect more than one trailing digit. First check the exceptional final pair, then use the final single digit for the general case:

const last_two = number % 100;
const last_one = number % 10;

This ordering prevents a general final-digit rule from incorrectly handling values whose final two digits form an exception.

Formatting rule: Keep semantic selection, such as choosing a suffix, separate from output allocation. Let formatting APIs calculate presentation length.

QUESTION 37

How do byte slices relate to UTF-8 characters?

A Zig string is a byte slice such as []const u8; the type does not store an encoding. A regular for loop therefore yields bytes, not Unicode code points. UTF-8 uses one to four bytes per code point, so slicing at an arbitrary byte index can split an encoded value.

utf8ValidateSlice scans one complete byte slice and returns one boolean. Placing that call in a formatting argument tuple evaluates it once:

std.debug.print(
    "valid UTF-8: {}\n",
    .{std.unicode.utf8ValidateSlice(text)},
);

The .{ ... } expression is an anonymous tuple of print arguments, not iteration. Repeated log lines usually mean the surrounding function was called repeatedly, such as once per test.

Iterate code points

const view = std.unicode.Utf8View.init(text) catch unreachable;
var iterator = view.iterator();

while (iterator.nextCodepointSlice()) |bytes| {
    // bytes contains one complete UTF-8 code point.
}

nextCodepointSlice returns the original bytes for one code point, while nextCodepoint returns its decoded u21 value. peek(n) returns a byte slice covering up to the next n complete code points without advancing the iterator.

Encoding rule: Encoding comes from the input contract, not the slice type. UTF-16 normally arrives as []const u16 plus a known byte order; arbitrary bytes cannot be reliably guessed to be UTF-8 or UTF-16.

Returning a prefix from the iterator does not allocate. It is a borrowed slice into the original input and remains valid only while that input remains valid. Code points are not the same as user-perceived grapheme clusters, but code-point truncation is correct when that is the stated contract.

QUESTION 38

How do I test divisibility and search divisor pairs?

An unsigned integer divides evenly when its remainder is zero:

if (divisor != 0 and number % divisor == 0) {
    // divisor divides number exactly.
}

Unsigned integer division discards the fractional part, but the remainder is still available through %. Signed integers require explicit @rem or @mod semantics; either can test equality with zero for divisibility.

Discover two divisors at once

When divisor divides number, its paired divisor is number / divisor. Every pair has one member at or below the square root, so searching beyond that boundary only rediscovers reversed pairs:

while (divisor <= number / divisor) {
    if (number % divisor == 0) {
        const partner = number / divisor;
        // Account for divisor and partner.
    }
    divisor += 1;
}

The division-based boundary is equivalent to divisor * divisor <= number for positive integers but avoids multiplication overflow. If divisor == partner, the number is a perfect square and that divisor must be counted only once. Domain-specific sums may also need to exclude the original number itself.

Overflow timing: Checking whether a sum exceeded its limit after sum += value is too late if the addition itself can overflow. When crossing the limit already determines the answer, compare value with limit - sum before adding.

Complexity: Scanning all candidates through half the number is O(n). Divisor pairing reduces the search to O(sqrt(n)) time with O(1) extra storage.

QUESTION 39

How do I parse formatted input with explicit state?

When only a small byte grammar is valid, use an exhaustive switch that states what is accepted. This is safer than ignoring every byte that is not immediately useful:

switch (byte) {
    '0'...'9' => {
        // Consume meaningful data.
    },
    ' ', '.', '-', '(', ')' => continue,
    '+' => {
        // Validate and record prefix state.
    },
    else => return null,
}

An empty branch such as => {} performs no operation. Inside a loop, => continue more explicitly says that an allowed separator skips the rest of the iteration. Switch prongs cannot overlap and do not fall through; combine identical cases or use an inner if when one value needs additional handling.

Remember obligations across separators

A marker may constrain the next meaningful byte rather than the next physical byte. Record that obligation in state, leave it unchanged while skipping formatting, and resolve it when data arrives:

if (prefix_pending) {
    if (byte != required_prefix) return null;
    prefix_pending = false;
    continue;
}

This small state machine rejects repeated markers and invalid prefixes while still allowing permitted separators between them. A fixed output array can begin as undefined when every element is written before success; return null unless the final initialized count exactly matches the required length.

Grammar rule: Define accepted bytes, rejected bytes, and pending obligations explicitly. Ignore only known separators, never arbitrary unknown input.

QUESTION 40

How do I return a result whose length is not known yet?

allocator.alloc always requires a runtime length. When the length becomes known only while processing, use a growable list that reallocates as elements are appended:

var result: std.ArrayList(u64) = .empty;
errdefer result.deinit(allocator);

try result.append(allocator, value);

return try result.toOwnedSlice(allocator);

toOwnedSlice transfers the list's allocation to the caller and empties the list. On an earlier error, errdefer releases partial storage. The successful caller owns the returned slice and must free it with the same allocator.

Capacity rule: An unknown-length result does not use an undefined-size allocation. It starts with zero logical length and grows capacity as needed.

Reserve a known upper bound

If the final length is unknown but has a cheap upper bound, reserve that capacity before appending:

try result.ensureTotalCapacity(allocator, maximum_items);

// Ordinary append reuses the reserved capacity.
try result.append(allocator, value);

Capacity is writable storage; the list length remains zero until values are appended. Preallocation can avoid growth reallocations but may reserve unused memory when processing stops early. Keep ordinary append unless an appendAssumeCapacity invariant is both obvious and worth enforcing.

Reduce trial division before optimizing storage

When repeatedly extracting factors, testing every candidate directly is enough; a separate primality test repeats work. Keep a successful candidate so repeated factors are preserved, and advance only after a failed division.

Stop when candidate > remaining / candidate. At that point any remainder greater than one is the final prime factor:

while (candidate <= remaining / candidate) {
    if (remaining % candidate == 0) {
        // Record candidate and reduce remaining.
    } else {
        // Advance candidate.
    }
}

// A remaining value greater than one is prime.

The division-based bound avoids multiplication overflow. Trying 2 and then only odd candidates removes unnecessary even checks without needing a prime-number helper.

Complexity: Trial division is O(sqrt(n)) in the worst case. The growable output uses O(k) memory for the k returned factors.

QUESTION 41

How do I switch on a fixed-width byte key?

Zig does not switch directly on arrays or slices. When a key is exactly three bytes, pack it losslessly into a u24 and switch on that scalar:

fn key(bytes: [3]u8) u24 {
    return (@as(u24, bytes[0]) << 16) |
        (@as(u24, bytes[1]) << 8) |
        @as(u24, bytes[2]);
}

The array parameter enforces the length at compile time, so no runtime assertion is needed. A string literal is a pointer to a sentinel-terminated array; "ABC".* dereferences it into an array value suitable for the fixed-size parameter.

return switch (key(input)) {
    key("ABC".*) => .first,
    key("DEF".*), key("GHI".*) => .second,
    else => error.UnknownKey,
};

Returning the switch directly gives enum literals such as .first the expected return type. An inferred local containing enum literals, null, and errors may otherwise remain comptime-only because Zig has no concrete runtime type to infer.

Recover a fixed array from a runtime slice

A dynamic range still has slice type and cannot be dereferenced. First take a runtime tail, then a compile-time-sized prefix:

const chunk: [3]u8 = input[offset..][0..3].*;

Check offset + 3 <= input.len first. This condition includes the final complete chunk and avoids the unsigned underflow caused by subtracting three from a shorter input length.

Key rule: Fixed arrays express width, packed integers enable switching, and an explicit result context turns enum literals into runtime enum values.

QUESTION 42

How do I wrap ASCII letters within their alphabet?

Adding directly to an ASCII byte does not wrap at 'z' or 'Z'; it continues into punctuation or non-ASCII byte values. Normalize the letter to an offset from zero, apply the cyclic operation, then restore its alphabet base:

const base: u8 = if (std.ascii.isLower(byte))
    'a'
else if (std.ascii.isUpper(byte))
    'A'
else
    return byte;

const offset: u8 = byte - base;
const wrapped = (offset + @as(u8, amount)) % 26;
return base + wrapped;

The base preserves case, while remainder keeps the normalized offset in 0...25. Apply % 26 to the offset rather than the raw ASCII code; the two alphabets begin at different numeric values.

Reflect letters and group transformed output

A reversed lowercase alphabet uses the same normalized-offset model, reflected from 'z':

const lower = std.ascii.toLower(byte);
const mirrored = 'z' - (lower - 'a');

When transformed output is grouped, count only bytes that survive filtering. Before appending the next retained byte, insert a separator if the current group is full, then reset the group count. Raw input indexes are unreliable because punctuation and whitespace may produce no output, and a final sixth retained character still needs a separator before it.

Byte-oriented rule: std.ascii classifies single-byte ASCII characters. Copy nonletters unchanged, and use Unicode-aware decoding when transformations must understand non-ASCII text.

QUESTION 43

How does a flag array implement a prime sieve?

Use each integer as an index into contiguous boolean storage. Begin with candidate values marked as possible primes, then clear composite indexes. A bounded integer input can justify fixed stack storage; for example, a u12 has exactly 4096 possible values:

var is_prime = [_]bool{true} ** 4096;

Starting at two avoids treating zero and one as primes. For each still-marked candidate, begin crossing out at its square:

var candidate: usize = 2;
while (candidate <= limit / candidate) : (candidate += 1) {
    if (!is_prime[candidate]) continue;

    var multiple = candidate * candidate;
    while (multiple <= limit) : (multiple += candidate) {
        is_prime[multiple] = false;
    }
}

Smaller multiples such as 2 * candidate were already cleared by smaller prime factors. The division-based outer bound is equivalent to testing candidate * candidate <= limit but avoids overflow in the condition.

After marking, scan indexes from two through the limit and copy marked values into caller-provided storage. Track the number written and return only that initialized prefix. The API must guarantee that the caller's buffer has enough capacity or provide an error channel for insufficient space.

Complexity: A sieve takes O(n log log n) marking time and O(n) flag storage. Contiguous flags and predictable strided writes are the central data-layout choice.

QUESTION 44

How do I compare slices and find a contiguous subslice?

Use std.mem.eql when two slices must contain the same elements in the same order:

const same = std.mem.eql(i32, left, right);

Use std.mem.find when searching for one complete slice inside another. It returns the starting index or null:

const position = std.mem.find(i32, haystack, needle);
if (position != null) {
    // needle occurs contiguously in haystack.
}

This is a contiguous sequence test, not set membership: order and repeated values matter. An empty needle is found at index zero, so empty-subsequence behavior does not need a separate search implementation.

Classify relationships in the right order

Check equality before containment because equal slices contain each other. When lengths differ, the shorter slice is the only possible needle and the longer slice is the haystack; preserve which original input was longer so the result direction remains correct.

Version note: In Zig 0.16, use std.mem.find. The older std.mem.indexOf name is a deprecated alias.

QUESTION 45

How do I convert digit sequences between arbitrary bases?

Use a numeric value as the bridge between representations. The intermediate integer is not a decimal digit sequence; it is a base-independent value held in an integer type.

Decode with multiply-and-add

Horner's method avoids calculating positional powers explicitly. Validate each digit before including it:

var value: u32 = 0;
for (digits) |digit| {
    if (digit >= input_base) return error.InvalidDigit;
    value = value * input_base + digit;
}

Validate both bases as at least two. Choose an intermediate type wide enough for the documented input domain, or use checked arithmetic when overflow must become an error.

Encode with repeated division

Each remainder is the next least-significant output digit, so collect remainders and then reverse them:

if (value == 0) try output.append(allocator, 0);

while (value > 0) : (value /= output_base) {
    try output.append(allocator, value % output_base);
}

std.mem.reverse(u32, output.items);

When the API transfers ownership, even the zero result must come from the allocator; do not return a slice backed by a static literal. Use errdefer output.deinit(allocator) before fallible appends and toOwnedSlice on success.

Scaling rule: A native integer bridge is simplest when the complete value fits. For arbitrarily large inputs, repeated division can operate directly on the source digit array. Power-related bases allow specialized grouping, such as four binary digits per hexadecimal digit.

QUESTION 46

How do I normalize text and read a rectangle by columns?

std.mem.trim removes selected bytes only from the two ends of a slice. To remove punctuation throughout immutable input, filter retained bytes into temporary owned storage:

var normalized: std.ArrayList(u8) = .empty;
defer normalized.deinit(allocator);

for (input) |byte| {
    if (!std.ascii.isAlphanumeric(byte)) continue;
    try normalized.append(allocator, std.ascii.toLower(byte));
}

Use defer for temporary storage needed only during the function; it must be released on both success and error. Use a separate result list with errdefer when its allocation transfers to the caller on success.

Transpose row-major data with index arithmetic

For a conceptual rectangle with columns entries per row, row r and column c map to the linear index r * columns + c. Swap the loop order to emit columns:

for (0..columns) |c| {
    for (0..rows) |r| {
        const index = r * columns + c;
        if (index < normalized.items.len) {
            try result.append(allocator, normalized.items[index]);
        } else {
            try result.append(allocator, ' ');
        }
    }
}

The bounds check models missing cells in the final row and supplies explicit padding. If chunks need separators, append them between outer-loop iterations rather than after the final chunk.

Layout rule: Keep normalized bytes contiguous, derive coordinates mathematically, and separate temporary ownership from returned ownership. The transpose remains O(n) even though it reads the input with a column stride.

QUESTION 47

How do I build a symmetric runtime-sized text grid?

An array type such as [N]u8 requires N at compile time. When dimensions depend on runtime input, allocate slices instead. If the final number of rows is already known, allocate the outer slice directly rather than growing an ArrayList:

const rows = try allocator.alloc([]u8, side);

const row = try allocator.alloc(u8, side);
@memset(row, ' ');

When each row is independently owned, track the initialized outer prefix and use nested errdefer cleanup as described in the error-path notes. A writer is useful for sequential variable-length output; direct indexing is clearer when every cell position is known mathematically.

Mirror one half into the other

For an odd-sized symmetric grid, map each row to its distance from the nearest vertical edge:

const rank = @min(row_index, side - 1 - row_index);
const center = side / 2;

row[center - rank] = symbol;
row[center + rank] = symbol;

The rank sequence rises to the center and then falls automatically. On the first and last rows both positions are the center, so writing the same byte twice is harmless. Deriving the symbol from rank avoids maintaining separate ascending and descending state.

Shape rule: Use runtime slices for runtime dimensions, initialize the full row background, then write only the positions defined by the geometry.

QUESTION 48

How do I reduce adjacent windows without a reduce method?

Zig normally expresses reduction with an explicit accumulator loop. Choose the identity value for the operation: zero for addition and one for multiplication.

var product: u64 = 1;
for (window) |byte| {
    if (!std.ascii.isDigit(byte)) return error.InvalidCharacter;
    product *= byte - '0';
}

For every adjacent window of width k, include start positions through input.len - k. A half-open slice and an inclusive end condition make the final window visible:

var start: usize = 0;
while (start + width <= input.len) : (start += 1) {
    const window = input[start .. start + width];
    // Reduce window, then update the best result.
}

Validate a signed width before converting it to usize. The empty product has value one, while a positive width greater than the input length is invalid. Use an accumulator type wide enough for the maximum possible result; longer input creates more windows, but only the window width controls one product's magnitude.

Boundary rule: Use <= so a window equal to the full input and the final shorter-offset window are both processed.

QUESTION 49

How do I compose cumulative text from reusable phrases?

When each successive output includes one new phrase followed by all earlier phrases, store the fragments from the shared ending outward:

const phrases = [_][]const u8{
    "the final phrase.",
    "the second phrase leading into ",
    "the third phrase leading into ",
};

For level n, write the fixed introduction, then traverse phrase indexes from n down to zero. This represents the cumulative structure as data instead of duplicating complete outputs or using recursion.

try writer.writeAll("This is ");

var phrase = level;
while (true) : (phrase -= 1) {
    try writer.writeAll(phrases[phrase]);
    if (phrase == 0) break;
}

The break must happen before decrementing zero because usize cannot represent -1. For a range of outputs, append separators only between complete entries. A fixed-buffer writer fits when the caller owns output storage and the result must point into that buffer.

Composition rule: Store changing clauses once, derive cumulative output by index order, and keep separator logic outside the phrase traversal.

QUESTION 50

How do generic intrusive linked lists model self and ownership?

A function returning type can build one concrete container type per compile-time element type. Inside the returned anonymous struct, @This() names that concrete type:

pub fn List(comptime T: type) type {
    return struct {
        const Self = @This();

        pub fn push(self: *Self, node: *Node) void {
            // Mutate the caller's list bookkeeping.
        }
    };
}

A pointer receiver is required for mutation; passing Self by value would copy the head, tail, and length fields. Use *const Self for read-only methods.

Represent edges and ownership explicitly

A linear doubly linked node uses optional pointers because its neighbors may not exist:

prev: ?*Node = null,
next: ?*Node = null,

The head's prev and tail's next remain null; connecting them would create a different data structure, a circular list. Appending repairs both directions: the old tail points forward to the new node, the new node points back, and the new tail's forward link is null.

When callers construct nodes and pass pointers into the list, the list is intrusive: it links but does not allocate, free, or own those nodes. Deletion repairs the remaining list; clearing a removed node's stale links is an optional defensive API choice unless detached-node state or node reuse is part of the contract.

Invariant: An empty list has null head and tail with length zero. A non-empty linear list has matching forward/backward links, null outer links, and a length equal to the number of reachable nodes.

QUESTION 51

How do tagged unions represent recursively nested data?

Arrays and slices contain one element type. A tagged union keeps that homogeneous storage while allowing each element to have one of several valid shapes:

const Box = union(enum) {
    none,
    one: i12,
    many: []const Box,
};

The tag guarantees exactly one active alternative. A struct with optional value and child fields would permit ambiguous states where both or neither are set. Recursive data must be indirect: the slice in many has fixed pointer-and-length size, while embedding another Box directly would require an infinitely large type.

Traverse by switching on shape

switch (box) {
    .none => {},
    .one => |value| try result.append(allocator, value),
    .many => |children| {
        for (children) |child| {
            try appendFlattened(allocator, result, child);
        }
    },
}

append accepts one element; appendSlice accepts a slice of elements. A recursive function that returns a newly allocated slice can be unwrapped, copied with appendSlice, and freed, but deeply nested values may be allocated and copied once per level.

For one-pass output, let the public function own one ArrayList and pass *std.ArrayList(T) into a recursive helper. Every call then appends to the same bookkeeping object. The root errdefer handles failure, and toOwnedSlice transfers the final contiguous result to the caller.

Modeling rule: Use a tagged union for mutually exclusive shapes, a slice or pointer for recursion, and one explicit owner for accumulated output.
